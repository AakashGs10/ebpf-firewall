How we leveraged Microsoft Azure and cloud-native tooling to deploy a production-grade security system.

systemd Service Management

The eBPF firewall runs as a production systemd service with auto-restart on failure, environment file for secrets, and proper lifecycle management.

Service: ebpf-shield.service
Restart: on-failure
Secrets: /etc/ebpf-shield.env
Lifecycle: ExecStartPre/StopPost

Cloud Threat Intelligence

The control plane periodically fetches live threat feeds from the internet (IPsum — 30+ sources) and injects malicious IPs directly into the kernel blocklist map.

Feed: IPsum (stamparm/GitHub)
Interval: Every 6 hours
Max IPs: 15,000 signatures
Injection: Direct to kernel map
🦠

ClamAV Antivirus Gateway

A file upload endpoint that streams files through ClamAV for malware scanning. Infected uploads are rejected and the sender's IP can be auto-banned at the kernel level.

Endpoint: POST /upload
Max Size: 20 MB
Concurrency: 4 scan slots
Auto-Ban: BAN_ON_INFECTED=1

Security Layers

Multi-Layer Defense in the Cloud

Five independent security mechanisms working together at kernel speed.

🚫

IP Blocklist

20,000-entry kernel hash map fed by live threat intelligence — blocks known malicious IPs instantly at the NIC.

⚡

Rate Limiter

Per-IP sliding window counter — drops packets exceeding 20,000 pps, protecting against DDoS and port scans.

🧩

Fragment Blocking

Zero-trust policy on fragmented packets — tracks and drops IP fragments used for evasion attacks.

🔍

Deep Packet Inspection

Inspects TCP/UDP payload for known attack signatures ("PWND") directly in the kernel data path.

🦠

ClamAV Antivirus

Uploaded files are scanned through ClamAV in real-time — infected files are quarantined and uploaders can be auto-banned.

🔐

Azure NSG + eBPF

Dual-layer firewall — Azure NSG controls cloud-level access while eBPF/XDP handles L3/L4/L7 inspection at kernel level.
